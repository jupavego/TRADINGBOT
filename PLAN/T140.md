# T140 — La API no se queda sorda sin que el vigilante lo note
Fase 21 · Depende: T126 T127 · Esfuerzo: medio · Skills: code-review (medium)

## Objetivo
Que una API sin puerto se detecte y se recupere sola en minutos. El 2026-11-06 estuvo más de 11 horas sorda con el proceso «sano»: `asyncio` cerró el socket de escucha tras un `WinError 64`, el latido siguió al día y ni el vigilante ni `continuity check` lo vieron. El diagnóstico con la evidencia está en `PLAN/notas/T140_api_sin_puerto.md` §1.

## Leer (solo esto)
`CLAUDE.md`, `PLAN/notas/T140_api_sin_puerto.md`, `v2/eim/operation/watchdog.py`, `v2/eim/operation/__main__.py` (lanzamiento de `uvicorn`), `v2/eim/continuity/` (el `check`), `v2/docs/RUNBOOK.md`.

## Entregables
1. **El vigilante mira el puerto.** Una conexión TCP a `127.0.0.1:<puerto>` rechazada de forma sostenida, una vez pasada una gracia de arranque, reinicia el proceso con el motivo «puerto sin escuchar», y deja alerta y registro. Se usa conexión TCP y no una petición HTTP por una razón: con el bucle bloqueado el sistema sigue aceptando la conexión, de modo que **un bloqueo no se confunde con un socket perdido**. La sonda es opcional, porque `Watchdog` también vigila otros servicios sin puerto.
2. **Reproducirlo.** Un script aparte que provoque el `WinError 64` en Windows: un cliente que resetea la conexión con `SO_LINGER 0` mientras el bucle está bloqueado, para `ProactorEventLoop` y `SelectorEventLoop`. Comprueba o descarta que el bloqueo sea la causa, que hoy es una hipótesis.
3. **Decidir el bucle con esa evidencia.** `SelectorEventLoop` solo se adopta si el socket sobrevive en la reproducción y no rompe nada. Hay que revisar: `--loop asyncio` no basta (`uvicorn/loops/asyncio.py:9-10` da Proactor en Windows), el límite de 512 sockets de `select`, y que `eim/` no usa `asyncio.create_subprocess_*` (hoy 0 usos). Si no se adopta, el entregable 1 queda como la defensa y se dice por qué.
4. **Los registros llevan hora.** `vigilante.{err,out}.log` no la tienen, y por eso el 2026-11-06 no se pudo fechar el fallo ni saber cuánto estuvo sorda la instancia anterior. Conservar el registro entre arranques, que hoy se reescribe.
5. **`continuity check` y la vista de estado dicen si el puerto escucha.**
6. **`RUNBOOK.md`:** síntoma, cómo confirmarlo y cómo reiniciar solo la API sin tocar la captura.

## Aceptación
Gate verde por la cola. Pruebas sin red externa con una sonda inyectada: socket perdido con latido al día → reinicia; bucle bloqueado con socket abierto → no reinicia por esta vía; arranque lento dentro de la gracia → no reinicia; servicio sin puerto configurado → se comporta como hoy. El informe de la reproducción dice qué bucle queda y por qué. Desplegarlo exige reiniciar la API: pedir permiso.

## Fuera de alcance
Por qué el equipo se satura (T141). Las operaciones congeladas (T142). Cambiar el umbral de 900 s del latido. Modificar `asyncio`.
