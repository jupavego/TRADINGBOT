# T33 — Auditoría de repos y fuentes para los 4 agentes nuevos
Fase 8 · Depende: — · Esfuerzo: medio · Subagentes: sí (un repo/fuente por subagente) · **Punto de decisión humana**

## Objetivo
Verificar con evidencia (no solo README) qué repos y fuentes de datos se pueden usar para copy trading, arbitraje, calendario económico e indicadores técnicos, y fijar el alcance de copy trading.

## Leer (solo esto)
`CLAUDE.md`, `PLAN/notas/T04_auditoria.md` (formato y criterios). La investigación previa del usuario es **hipótesis sin verificar**: viene de README, no de lectura de código.

## Candidatos a auditar
- Copy trading: `incorebot/binance-scrape2trade` (extensión + endpoints no documentados), `MaxIsOntoSomething/Hyperliquid_Copy_Trader`, `Gajesh2007/copytrading-agent` (reconciliación; se declara "no auditado"), `Hype-W/app-hyperliquid-copy-trading` (solo inspección). API pública oficial de Hyperliquid (info/WS).
- Arbitraje: `hummingbot/hummingbot` (Apache-2.0), `counterfactual5/funding-arb`, `aoki-h-jp/funding-rate-arbitrage`, `ccxt/ccxt`, `MfaXyz/Crypto-Triangular-Arbitrage-Bot` (su README advierte pérdidas), `rayguang/cryptocurrency-binance-triangulararbitragebot`. Solo Binance: preferir el conector oficial antes que CCXT.
- Indicadores: TA-Lib, pandas-ta (verificar si sigue mantenido), `ta`, tulipy. Criterio: licencia, mantenimiento, dependencias nativas en Windows, precisión frente a referencia.
- Calendario: FRED (releases), federalreserve.gov (FOMC), BLS/BEA, Finnhub, Trading Economics, feeds comunitarios. Criterio: licencia/ToS, valores previstos/reales/revisados, latencia, coste, zona horaria.
- Sitios de seguimiento (HyperStats, HyperTracker, HyprSwarm, HyperX): solo como referencia de métricas; no se integran como dependencia.

## Entregables
1. `PLAN/notas/T33_auditoria.md` con alertas primero y tabla de veredictos (Usar / Referencia / Descartar), como T04: licencia en archivo `LICENSE` real, última actividad, tests, manejo de claves, red/telemetría, `exec`/`pickle`. Clones aislados fuera del proyecto, **sin ejecutar ni instalar nada**.
2. Revisión de los términos de Binance sobre el leaderboard de copy trading y los endpoints no documentados: ¿se pueden consumir? Si no está claro → no se automatiza (solo uso manual/analítico).
3. Propuesta de alcance para el usuario: fuente de líderes (Hyperliquid público oficial como base; Binance solo si lo permiten los términos), modo (señales y alertas → simulación → testnet) y fuente del calendario.

## Aceptación
Veredicto por cada repo/fuente con enlace a la evidencia; alcance propuesto presentado al usuario. Sin su visto bueno, T40 no empieza.
