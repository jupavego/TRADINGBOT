# T08 — API v2 (REST + WebSocket + persistencia)
Fase 2 · Depende: T05 · Esfuerzo: medio · Skills: run

## Objetivo
Servidor FastAPI que expone snapshots, reportes de agentes y un canal en vivo, y persiste cada reporte.

## Leer (solo esto)
`CLAUDE.md`, `PLAN/CONTRATOS.md`, `eim/agents/runner.py`, `eim/data/snapshot.py`.

## Entregables
1. `eim/api/main.py`: `GET /v2/health`, `/v2/snapshot?symbol&tf&n`, `/v2/agents` (lista y estado), `/v2/reports?symbol&tf` (últimos reportes), `/v2/overlays`.
2. `WS /v2/stream?symbol&tf`: emite (a) tick de la vela en formación (desde el WebSocket de klines de Binance), (b) al cierre de vela: nuevos reportes de agentes + overlays. Reconexión automática, latido, y mensaje de estado si cae la fuente.
3. Persistencia de `AgentReport` en DuckDB (`reports`), consultable por rango; base de la bitácora y la calibración.
4. Configuración por variables de entorno (sin claves en código). CORS para el frontend en desarrollo.
5. Tests con cliente de prueba y fuente simulada.

## Aceptación
Gate pasa. Levantar el servidor (usar `127.0.0.1`), conectar un cliente WS de prueba y recibir ticks y, al cierre simulado, reportes. Los reportes quedan en DuckDB.

## Fuera de alcance
Frontend; endpoints de pronóstico (T17); ejecución de órdenes.
